**Responsibility:** retain complete acquired text while admitting a useful, explicitly partial set of Python analysis units under existing resource limits. This experimental successor specializes the [native adoption plan](CALLER_SIGNATURE_NATIVE_ADOPTION_AND_QUALIFICATION_PLAN.md); it does not change product authority or authorize arbitrary larger budgets.

## Included capability, cost and exclusions

The product responsibility remains conditional target-rooted source evidence across the already qualified direct/import/initializer/protocol forms. The successor includes conservative static import-component selection, whole-file atomic admission, paired captured native module admission and external-origin root priority. All captured text remains in the companion and outer source packets; only the admitted units supply facts/candidates.

Unconnected target files, over-budget units and their potential dynamic relationships remain explicitly unexamined. Static scope is an analysis allocation heuristic, never absence/runtime binding proof. A large connected component may still be only partially admitted; an oversized required unit may remain unsupported. These are temporary capability limits, not declarations outside the broader product responsibility. Re-enter when retained cases demonstrate that useful evidence needs finer-grained admission or a separately measured resource profile. No case-specific repository/path/dependency/version/expected verdict selectors are allowed.

## Admission algorithm

1. Under the worker's existing time/memory limits, scan all selected Python modules with non-executing AST parsing. Enforce existing per-file and aggregate AST-node limits on all scanned source, including subsequently unexamined files. Invalid syntax remains unresolved, not an absent dependency use. Record unique scanned nodes separately from admitted fact work.
2. Inspect syntactic Import/ImportFrom module names, including conditional imports and existing relative-import normalization. Target modules with a possible syntactic connection to any captured non-target module seed scope. Close target-to-target import connections in both directions within the same source identity, keeping callers and helpers together. Ambiguous matching module layouts remain alternatives. With no captured external modules, retain the target-only fallback responsibility rather than claim no exposure.
3. Admit captured native old/proposed versions of the same package/module as an atomic group; samples retain their distinct identities. Process library groups before target groups, using deterministic module/source ordering. This protects both captured sides from unrelated target work; it does not prove paired call correspondence.
4. Extract each considered file with the unchanged scoped binder/call/signature owner and original per-file limits. Admit whole groups only when total facts/nodes fit. Otherwise retain text, mark every affected unit unexamined with the actual reason, and continue to later groups without fabricating partial facts. Source syntax errors produce the existing problem facts. No per-fact slicing or known-witness paths.
5. Explore admitted target roots whose imported alternatives reach captured external module namespaces before the other admitted roots, preserving conditional/unknown binding states. This is priority only; resolver/checker/premises and candidate/path/state limits remain unchanged. Exhaustion must remain visible and cannot imply all roots were compared.
6. Emit one typed admission row per Python module: exact source unit ID, admitted/unexamined state, reason and scanned node count. Admitted units retain complete-file facts; unexamined units retain complete text with coverage=unexamined and facts=None. Include all source files/modules and an explicit partial coverage statement in the result/companion.

## Fixed-reader and presentation proof

The reader does not reparse source or rerun admission/discovery/checking. It validates the supported profile, exact Python unit membership, state/reason/coverage/fact consistency, scan-node limits and equality for analyzed units, paired captured native group state, source/fact/span/path membership and existing work/resource bounds. Any path step into an unexamined unit refuses. An analyzed Python unit missing facts still refuses; a legacy format cannot opt into missing facts. Raw source remains inspectable offline even if no facts were admitted.

Rendering distinguishes complete retained text from partial analysis, lists every unexamined unit/reason and scan/admitted work. Useful paired facts with any unexamined unit are useful_partial_structural_evidence. No native pairs remains insufficient; a completed worker is not compatibility/runtime/maintainer authority. Final JSON/output capacity failures remain recorded refusals, not hidden record truncation or automatic retries.
