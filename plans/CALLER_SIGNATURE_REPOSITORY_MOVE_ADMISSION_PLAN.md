# Caller/signature repository move admission plan

## Responsibility and entry evidence

Allow the normal caller/signature workflow to examine public library source when an otherwise admitted exact-release declaration names a repository that GitHub has moved. Preserve the declaration, the observed link between the names, and the identity of each examined file. The [AV-Tracer acquisition](../working-memory/2026-11-10_av-tracer-split-route-qualification_cycle.md) and [separate GitHub control](../working-memory/evidence/2026-11-10-av-tracer-split-route-qualification/redirect-control.json) establish the qualifying response shape. [ADR-0011](../docs/architecture/ADR-0011-explicit-source-association-bases-and-proposal-boundary.md) governs declaration and examination authority. [ADR-0013](../docs/architecture/ADR-0013-versioned-native-reconstruction-and-workspace-checkpoint-storage.md) governs retained reconstruction.

## Provider observation and source admission

1. Keep association eligibility where it is. Start with the repository already admitted by `associate_declared_source` for the exact release. Existing ambiguous declarations or adverse publisher observations still block association. Apply move admission only to the initial tag-reference lookup of a caller/signature library release. Keep automatic redirects disabled. The shared GitHub API may expose the narrowly requested response header to the tag lookup while retaining existing behavior for its other consumers.
2. Admit one move only from HTTP 301 with one unambiguous `Location` equal to `https://api.github.com/repositories/<id>/git/ref/tags/<encoded-tag>`. Require a canonical positive decimal ID and the exact encoding used for the requested tag. Reject credentials, ports, query strings, fragments, different tags, other statuses and other destination shapes. Parse for validation and construct subsequent requests from validated identities under the existing GitHub session. Treat the header as provider evidence, subject to the repository and tag checks below.
3. Read GitHub repository metadata by ID. Require an exact integer ID match, an explicitly public repository, and a valid canonical `full_name` distinct from the declared identity under case folding. Check the canonical named repository endpoint returns that same public ID before using the existing name-based tag, tree and file clients. This reverse check is an additional qualification obligation beyond the three retained control GETs. A conflicting identity, malformed response, private repository, unavailable lookup or further redirect leaves the move unresolved.
4. Resolve both existing release tag spellings under the verified canonical name. Preserve the same rule of at least one exact resolved tag and one shared commit among all resolved spellings. Refuse if a tag previously observed at the declared name disagrees with its canonical observation. Existing peel, tree, file and digest guards apply. Reuse one verified repository mapping within the invocation and reestablish exact tags per release. Keep ordinary 404 behavior and the ordinary no-move path. Any move verification refusal remains local to the affected source observation and uses the existing partial-result and transport-stop machinery.
5. Charge every request to the same request, byte and elapsed-time ledger. Keep the existing stage reserves and invocation limits. The successful path adds two repository metadata GETs per verified mapping and at most two canonical tag-reference reads relative to the original name probes, plus normal tag peeling. Preserve available progress when a budget or provider failure interrupts the work. Cap the move at one hop and keep failures terminal for that observation, without retry or a cap increase.

## Retention and reconstruction

The [source acquisition owner](../src/upgradepilot/caller_signature/source_acquisition.py) retains the declared association. The source observation adds the requested tag, verified GitHub ID and canonical name, validated redirect path and provider outcomes in the shared request ledger. Retain the exact canonical tag and commit and bind them to each admitted file's canonical repository, revision, path and hash. Represent partial observations explicitly, including when the redirect was observed and verification or later file acquisition failed. Retain only validated public identity values and bounded refusal reasons. Keep raw unsafe locations, headers and credentials out of retained evidence.

The [source-family reader](../src/upgradepilot/caller_signature/source_codec.py) currently joins the declared repository directly to tag and file identity. Give the new shape a successor native source codec using the [Workspace codec owner](../src/upgradepilot/workspace/native_codecs.py). Keep existing source records readable under their original version. The successor reader accepts a declaration-to-file repository difference only through the typed move observation and exact joins. Validate version dispatch in capture, checkpoint reconstruction and projection. Keep the comparison family and report schema when they can consume that source family and show a stable citation to the declared association and canonical source. Review any necessary contract change with its owner before implementation expands.

## Qualification and stop conditions

- Use deterministic provider fixtures for the verified move, both tag spellings, unchanged direct acquisition, and the effects of disagreement or missing evidence. Cover wrong host, ref and ID, canonical lookup mismatch, nonpublic metadata, a second redirect, conflicting tags, and shared budget exhaustion before move verification completes. Assert refused destinations never receive a request and no failed verification admits source text.
- Exercise the ordinary Workspace path with moved source material, a partial move and a no-move case. Reopen a historical source record and the new record offline. Check exact file delivery and rejection of broken declaration, repository ID, tag, commit and file joins. Confirm other GitHub tag consumers preserve their previous behavior.
- After deterministic qualification, use a separately authorized and labelled normal AV-Tracer successor at the same base and head, using the established split route and the same caps. Preserve the prior captures. Record whether the relevant FastAPI source is admitted and where the source chain reaches next. Qualify the conflict only when the report exposes the relevant target call, sampled forwarding and both HTTPX signatures with their conditional scope and cold-recoverable citations. Record the first remaining gap if any.

Repository continuity supports source examination under the original declaration basis. Installed versions, exercised dispatch, release-artifact equivalence and maintainer decisions require their own evidence.
