## Repeated stable candidates

- public locator can begin acquisition;
- invocation remains separate from discovered identity;
- exact repository/base/head/change identity is mandatory;
- dependency path and role are first-class, multi-axis evidence;
- CI authority requires trigger, job, step, command, responsibility, revision,
  environment, and retention context;
- missing, expired, inaccessible, superseded, and failed-method evidence can create
  actions or method degradation;
- operations, evidence, transformations, findings, decisions, reports, follow-up,
  review, and ownership are distinct responsibilities;
- conditional stages require activation conditions;
- stopped work and non-activation can be affirmative runtime state;
- report projections are not truth stores;
- merge history is action, not correctness evidence;
- structural validation is credible deterministic work;
- AI-generated completion does not establish Ali-owned capability.

## Conditional responsibilities and artifacts

- advisory and exploitability analysis;
- framework/adapter compatibility;
- package identity and hash verification;
- repeated execution comparison and `CHECK_EXECUTIONS.jsonl`;
- causal failure attribution and `FAILURE_ATTRIBUTION.json`;
- semantic-version and declared-range analysis;
- stopping/cost evaluation and `STOPPING_EVALUATION.json` where material;
- dynamic or isolated execution;
- private or credentialed acquisition;
- platform/native/compiler/toolchain analysis;
- post-merge publication or deployment evidence.

Conditional work must not become a universal stage or artifact.

## Contradicted or narrowed assumptions

- one dependency-role enum is adequate;
- direct imports are the only relevance path;
- green or red workflow color has global authority;
- workflow name identifies the failed responsibility;
- advisory or CVE vocabulary always requires exploitability analysis;
- one comparison proves identical-environment causality;
- peer-suppression flags prove compatibility;
- every case requires dynamic execution or deep investigation;
- one narrative file represents the runtime;
- the full investigation must change the broad action or add a check to create value;
- completing the full runtime requires activating every conditional stage;
- more artifacts or more investigation mean higher quality;
- manual success proves automation.
