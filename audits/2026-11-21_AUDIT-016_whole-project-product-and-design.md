## Executive assessment

UpgradePilot is a working bounded evidence advisor. It now delivers exact dependency transitions, scoped CI command evidence, artifact and conditional Python-support findings, opt-in caller/signature analysis with historical CI observation, and inspectable saved results. The strongest demonstrated advance since October is preservation of **decision-relevant scope** from the original source through report and selected recovery paths. MapProxy now distinguishes eight job contexts and seven eligible command observations. ApplyPilot identifies the failed consuming step. AV-Tracer keeps a conditional source comparison distinct from a particular observed CI error. These are useful engineering capabilities even while the maintainer action is `abstain`.

Two trust controls should precede broader acquisition or AI work. The shared PR observation path accepts provider data explicitly marked private or internal in controlled tests of the existing path. The default local-model transport disables ambient proxy handling but inherits automatic redirects. Both conflict with an accepted trust boundary. The audit established the implementation discrepancies locally, with no private repository read or remote prompt transmission. [Finding F1](#audit-016-f1--high-public-target-admission-is-unenforced) · [Finding F2](#audit-016-f2--high-local-model-transport-inherits-redirects)

The central product investment question remains open. Tested implementation accuracy and exposed report reviews support a next engineering choice. We still lack an independent comparison showing that a maintainer makes a better or faster decision with the report. Resolve the trust controls, then choose a decision-changing product comparison before funding more general reasoning or infrastructure. The clearest deterministic capability candidate is an exact peer-pin conflict check. The clearest AI candidate is a bounded explanation of one already-verified finding, compared with a deterministic view of the same evidence. Neither candidate has earned general adoption. ## Findings and dispositions

### AUDIT-016-F1 — High: public target admission is unenforced

**Confirmed contract discrepancy.** The Charter limits the product to public repositories. The shared PR observation path constructs its trusted repository name from the request and parses number, author, base/head and changed-file count. It does not inspect the returned base repository visibility. CLI anonymous-by-default, explicit token acquisition, and exact changed-file snapshot checks address other problems. In two controlled provider responses, one explicitly private and one internal, the same observation path admitted the PR and retained its synthetic description. The shared prefix feeds both ordinary and caller/signature operation. A repository-move helper already checks public visibility, but that helper is on the separate canonical-name resolution path. [Charter boundary](../PROJECT_CHARTER.md#5-frozen-90-day-product-boundary) · [PR observation and parsing](../src/upgradepilot/github/pull_request.py#L142) · [Shared prefix](../src/upgradepilot/investigation_inputs.py#L60) · [Public repository verification](../src/upgradepilot/github/repository.py#L110)

**Impact and owner.** An explicitly authenticated reader could admit out-of-scope evidence when the provider returns it. This review used synthetic responses, with no private data exposure or proof of a real authenticated incident. The earliest sufficient owner is the GitHub target admission boundary, before description retention and changed-file fan-out. Qualify how canonical repository identity and publicness are asserted, including the treatment of absent evidence, public forks and repository moves. Add normal-path private, internal, missing-visibility and valid-public controls. Preserve explicit acquisition errors and the current snapshot guarantees.

### AUDIT-016-F2 — High: local model transport inherits redirects

**Confirmed control gap by source and installed-interface inspection.** ADR-0006 binds the local inference path to loopback, and the default session correctly disables ambient proxy handling. The normal wrapper still uses Requests' automatic redirect default. The extractor sends the candidate window to the loopback address, then classifies the final HTTP response. The installed Requests signature and a mocked send through the actual wrapper confirmed the inherited policy. The existing transport tests cover ambient configuration. This audit exercised neither a redirect destination nor a model/provider call. [ADR transport boundary](../docs/architecture/ADR-0006-bounded-local-support-drop-semantic-extractor.md#security-and-transport-boundary) · [Loopback session and request](../src/upgradepilot/upstream/support_drop_extractor.py#L69) · [Existing transport controls](../tests/test_lm_studio_loopback_transport.py)

**Impact and owner.** The initial URL and ambient proxy setting do not guarantee that the evidence stays within the admitted local endpoint throughout transport. Require the local transport to refuse redirects, preserve the resulting explicit unresolved state, and verify redirect refusal and ordinary loopback success with synthetic inputs. Keep the model policy and source grounding as distinct controls.

### AUDIT-016-F3 — Medium: ordinary acquisition has uneven resource enforcement

**Observed design gap with unmeasured operational consequence.** Ordinary GitHub JSON acquisition uses per-request timeouts, then decodes the response through Requests. The shared client has no body-size check before JSON decode. Individual changed-file counts, CI collections, and source-text formats have narrower bounds. PyPI JSON and selected job-log readers enforce streamed response caps. The explicit caller/signature source session accounts for eligible requests, bytes and cooperative elapsed time, and the live qualification supervisor enforces a separate process limit. Ordinary CLI composition instantiates separate clients, so the latter two mechanisms supply no shared ordinary CLI budget. [GitHub transport](../src/upgradepilot/github/api.py#L128) · [PyPI body bounds](../src/upgradepilot/pypi/api.py#L87) · [Caller/signature policy](../src/upgradepilot/caller_signature/acquisition.py#L30) · [Ordinary client composition](../src/upgradepilot/investigation.py#L204) · [Supervisor proof](../working-memory/evidence/2026-11-13-qualification-supervisor-timeout-repair/RESULTS.md)

**Disposition.** Prioritize the earliest provider boundary for an explicit complete-body limit and truthful refusal. Decide if an end-to-end ordinary budget is warranted from the actual fan-out and representative budget controls. Keep the selected log path, capped file representation, request timeouts and process supervisor accountable for their distinct duties. Retained case runtimes provide case observations. They provide no measured ordinary workload distribution or established global ceiling.

## Investment decision

1. **First**, select the two bounded trust repairs identified by F1 and F2 with an ordinary-path negative control for each. The defects are independent and each belongs at its producer boundary. Broader acquisition or model coverage would expand responsibilities before those guarantees are earned.
2. **Then** compare a maintainer decision over an exact retained case and an equally supplied baseline. Choose one task whose outcome can change the next priority. Where reviewer availability limits the independent study, use the existing development inputs to choose a testable product question and preserve independent usefulness as open.
3. **Choose the cheapest discriminating capability next.** Exact peer-pin consistency is the strongest competing feature because ApplyPilot provides direct deterministic evidence and an observed report gap. Its priority rises if a compatible and missing-metadata contrast demonstrate that peer selection is bounded and useful. An explanation pilot rises only if the material proposition is already established and a simpler presentation still leaves the decision unclear. A recurring empty evidence path raises acquisition or applicability work before either.
4. **Defer broad migrations and open-ended AI investment.** Reassess a Workspace consumer cutover when a named user path needs it or exposes divergence. Reassess retrieval and tool orchestration when their comparison can materially change a bounded decision.

The [Charter](../PROJECT_CHARTER.md) and accepted specs own allowed product and action effects. Findings and recommendations here are evidence for later selection.
