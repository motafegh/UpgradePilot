**Date/horizon:** November6, 2026; product `1e5d3aec` (source `dcee66e4`), timing methods `d436da0e`/`828546b2`. **Procedure:** `UP-SKILL:upgradepilot-repository-audit`. **Evidence:** [completed host measurement](../working-memory/evidence/2026-11-06-independent-host-timing/RESULTS.md), [all60 page contents/boundaries](../working-memory/evidence/2026-11-06-independent-host-timing/PAGE_INVENTORY.md), [machine inventory](../working-memory/evidence/2026-11-06-independent-host-timing/page-inventory.json), [consumer](../src/upgradepilot/workspace/consumer_access.py), [host delivery](../src/upgradepilot/workspace/lifecycle_host.py), [store publication](../src/upgradepilot/workspace/checkpoint_store.py), [Core JUST-*](../docs/specifications/UPGRADEPILOT_CORE_PIPELINE_AND_CONTRACT_SPECIFICATION.md#3-stable-project-invariants), [ADR-0012](../docs/architecture/ADR-0012-canonical-investigation-workspace-and-recovery-boundary.md), [ADR-0013](../docs/architecture/ADR-0013-versioned-native-reconstruction-and-workspace-checkpoint-storage.md).

## Observations and findings

**AUDIT-015-F1 — Confirmed granularity/calibration gap, not an established4096-character optimum.** `native_page` inherits default/hard maximum4096 from its introduction in `77d33dc1`, initially the CI/runtime native adapter. Inspected introduction/source and its directly relevant handoff demonstrate a bounded overflow route and controls, not measured calibration of that exact number. It limits delivered characters, not decoded family size or total per-request CPU. Do not invent a memory-page/SQLite alignment rationale. Current full-native offering defaults256KiB and permits at most1MiB; this comparison record is1,669,418ASCII characters/bytes and does not fit. That explains current refusal, not a fundamental inability to read a larger local record.

**AUDIT-015-F2 — Confirmed verbose/repeated candidate payload; simplification opportunity requires owner/design.** Candidate array occupies237,869characters; step-expression JSON string values occupy204,242 (~85.9%). Identical source-unit/span/operation/expression tuples, counted once, occupy86,002; repeated tuples therefore contribute118,240characters. Several class/function expression values contain complete bodies, not a short signature/path label. Original files are also retained. This establishes repetition and its cost, not that every source expression may be deleted safely. Candidate identity, ordered paths, role/version, comparisons, source-span relationships and premises remain meaningful. The native producer/codec contract owns lossless normalization or representation changes. A narrower consumer projection can often avoid returning entire bodies while retaining source references and original inspection access; it must not silently remove necessary premises/coverage or reinterpret a source hypothesis as runtime binding.

The60-page prefix is only part of the1,669,418-character record. It completes candidates but only begins the discovery-gap array; most unit/fact tables and work/overall-state fields occur later. Current partial_payload disclosure is honest, so this is not a demonstrated false completeness claim. It does show why arbitrary character paging does not align naturally with a question that needs a root's alternatives plus global partiality/coverage. A root projection must bring necessary global limits/gaps forward rather than treating complete candidates as a complete applicability assessment.

**AUDIT-015-F3 — Confirmed expensive durable raw route; repeated validation is an investigation target.** The qualified instrumented outer run is2380.532s;60 page calls consume2338.556raw seconds and2337.075process-CPU seconds, with first/last calls18.123/69.005raw seconds. `_validate_native_material` reconstructs the full relevant family before slicing. `_deliver` records each exact response, and each `CheckpointStore.publish` reads/validates all retained history roots. The view and original-basis caches already reduce distinct retained bases/repeated original decoding; they do not eliminate these other costs. Source plus the increasing CPU-heavy curve support profiling these paths, not a claim that disk fsync or one named function accounts for all time.~40minutes is a measured limitation of this instrumented route, not an inherent cost of truthfulness or evidence integrity, nor a universal normal-PR duration.

**AUDIT-015-F4 — Accepted guarantees must be separated from cadence and inspection semantics.** Purpose/scope/current-method checks control each actual access. Exact delivery/material relationships distinguish available data from what a consumer received. For the current durable interaction mode, ADR-0013 requires commit before successful canonical acknowledgement; removing persistence but returning the same acknowledgement would weaken recovery. That does not require arbitrary GUI scrolling or all passive offline inspection to create canonical publications: CLI saved report/source opening already reads without a new host delivery. Nor does the guarantee uniquely require repeatedly decoding the same immutable data or the present all-history algorithm. Cross-transaction cache reuse must not hide corruption/material/method changes. Any batching/volatile-inspection mode needs explicit acknowledgement, crash-loss, citation and recovery semantics in its actual owning plan/ADR; it is not an unreviewed flag optimization.

## Recommended order and alternatives

1. Define the actual consumer question and compare the existing report/source route with raw access. The earlier retained engineering task recovered its required witnesses through report/source navigation; independent usefulness and live normal-product review remain unproved. Do not assume every consumer must download the entire candidate array before answering one-root questions.
2. Prefer a reusable question/root-scoped native projection for an interactive caller/signature consumer if that need is selected. Return every matching alternative, old/proposed role/version and local outcome, ordered path/source references, required premises and relevant global coverage/stop/gap information. Retain exact original code access. This is selection/presentation, not a new analyzer or an HTTPX-specific shortcut. Compare with existing report/source behavior before adding it.
3. Calibrate page fallback if raw export/paging remains necessary. For the same245,760-character prefix,1024-char chunks need240responses,4096 need60,16,384 need15,32,768 need8(with a shorter last response). These are arithmetic request counts, **not measured speedups** or permission to change caps. Qualify wire-byte/escaping bounds, consumer context/latency, unchanged evidence, crash/recovery granularity, provenance and method/limit identity. Larger pages are currently refused; smaller pages increase calls and cannot complete this prefix within the existing64-page test ceiling.
4. Profile the dominant owners and investigate correctly scoped reuse of already validated immutable projections/records within a stable boundary/locked transaction. Preserve per-request authority and every distinct relationship/corruption check. Require discriminating wrong-material/method/history/corruption and acknowledged-recovery proof. Do not add a global unchecked cache or skip historical validation by assumption. Maintain current durability initially so the first repair does not also become a persistence redesign.
5. Reassess batching/read-only inspection only if the consumer responsibility and remaining measured costs justify it. Exact delivery can remain a separate fact even when several events commit atomically, but acknowledgement/loss boundaries and capability-intent-before-effect ordering must stay honest. A new event-store framework is not selected by this review.

## Disposition and non-findings

The findings support a bounded access/cost design decision before treating this raw API as an interactive baseline. They do not by themselves block all report/source-based native product qualification or authorize a repair. Preserve the measured limit in the eventual task/adoption disposition and explicitly choose the follow-up; do not let it disappear behind another case campaign.

No incorrect native comparison, source loss, historical rewrite, runtime execution, hidden provider work or violated current checkpoint-acknowledgement guarantee was demonstrated. No measured optimal page size, per-function CPU attribution, quantified guard overhead, independent maintainer benefit or universal latency is established. The full1.67MB body is already decoded internally for validation; paging is not proof that only4096characters are processed per request. Hidden full references did not complete missing deliveries.

Keep original source/captures/codec meaning and current guarantees until a justified selected design says otherwise. Re-enter on explicit selection or when a required normal consumer needs detailed native access at practical latency. This audit remains an unselected implementation opportunity; `MEMORY.md` alone owns the live decision and continuation.
