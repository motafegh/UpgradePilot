## Design decisions and proof limits

All three cases were already exposed during development. The set is not a held-out benchmark, training dataset, or independent product acceptance result. Curated-evidence presentation review tests communication of supplied evidence; normal product-output review requires an actual captured result, predeclared capability scope and revision alignment. The simulation's broader facts cannot be injected into product output and then called discovery proof.

The rubric separates comparability, claim discipline, useful finding coverage, full/partial case acceptance and reviewer comprehension. A critical overclaim cannot be averaged away. An unsupported case cannot disappear from the reported denominator, and blanket abstention does not demonstrate useful coverage. No automatic semantic judge, runner, dependency or generic evaluation platform was added.

The persisted-object case is a future capability/claim-limit control, not a demand that distribution-artifact serviceability handle saved ML models. Static base workflow records do not establish exact-head runtime results. The first actual review must retain these distinctions.
