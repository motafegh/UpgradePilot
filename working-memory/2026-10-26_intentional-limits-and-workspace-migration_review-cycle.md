## Workspace migration: actual target and implemented state

Accepted ADR0012 intends native producers/evaluators → one evolving Workspace → consumer projections, with eventual retirement of legacy snapshot plumbing. ADR0013 supplies representation/storage method. Domain facts remain owned by native modules; Workspace owns identity/composition/history/recovery rather than replacing domain evaluators. The migration plan explicitly permits stages while preserving the full target.

| Responsibility | Current inspected state | What remains |
| --- | --- | --- |
| Native identity/material capture and reconstruction | Inputs, CI/runtime, upstream/Python-support closure and later PR description have codecs/projections; hidden input closure and typed recovery have tests. | Complete selected family ledger; artifact branch/full-report/synthesis coverage is not established by this initial registry. Nested package metadata in another retained family does not supply the full artifact consumer closure. |
| Immutable revisions/local durable publication | Checkpoint store, optional durable host, transaction/predecessor/publication, backup and version refusal exist. | Default normal orchestration remains volatile; library support does not deliver user-selected durable recovery through the public CLI. |
| Lifecycle, host admission and material basis | Normal selected target-declaration read publishes intent/result/native feedback; host restoration clears authority/live admissions and requires present configuration/new admission. | Generic semantic conflict/adequacy competence is unsupported. More lifecycle bookkeeping does not establish it. |
| Direct native consumers | Native CI/Python projection APIs, a shared native-CI report consumer and direct PR-description report reconstruction exist. | Full report still reads most PublicPullRequestInvestigation fields; synthesis reads that result too. Do not claim all report consumers are legacy or all are migrated. |
| Legacy retirement | Normal orchestration evaluates owners once and returns both workspace_revision and fields from those same evaluations. | This is transitional plumbing, not two independent investigations. Complete consumer/family coverage and parity before removing fields. No divergence was demonstrated here; no claim of complete one-way Workspace-only projection is justified. |
| User recovery/continuation/replay | Saved report open is offline display; library host/store can inspect/reconstruct supported historical state. | Public CLI has save/open/source inspection but no Workspace checkpoint recovery/continuation interface. Recovery is distinct from validated continuation; deterministic replay remains separately unfulfilled. No exactly-once/power-loss promise is earned by process/store tests. |

Dependencies for a credible final cutover are concrete: define admitted family scope and consumers; retain missing actual material/conclusions at native owners; add supported cold projections; migrate normal report/synthesis consumers and preserve historical conclusions without reevaluation; expose the selected supported recovery/continuation operation with current-authority checks; prove parity/refusal/installed behavior; retire only plumbing whose remaining consumer/compatibility purpose is gone. Replay needs its own input/method/equivalence contract, not renaming report reopen or checkpoint restore.

The partial state has an explicit historical reason: the migration plan's interface-readiness handoff allowed bounded Investigator work before full-family/report migration. That readiness work was done, but later model delivery/interpretation results did not complete consumer cutover. Therefore this is neither a forgotten architecture nor a finished migration. Repeated product work should trigger an explicit scope/priority/defer review rather than assumption that temporary automatically remains appropriate.
