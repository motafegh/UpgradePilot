- module/source-closure limit vs provider timeout;

- retained source with explicit `unexamined` units vs missing/corrupt facts for a declared analyzed unit;

# Checkpoint F — Native product adoption and semantic equivalence — NEW

This checkpoint exists because productization is now the selected engineering responsibility.

## F1 — Product owner map

Understand the difference between frozen experiment adapters and the future active product owners:

- native source/comparison record families and codecs;
- native capture/staged publication;
- native projection/version admission;
- application/investigation orchestration;
- Workspace/report/source/store/recovery.

Target architecture: one evolving active analysis kernel owned by product code, while historical experiment readers remain frozen compatibility artifacts.

## F2 — Native representation and capacity

Understand what must survive transfer:

- exact source/material identities;
- facts/paths/roles/premises/outcomes;
- normalized binding traces;
- analyzed vs explicitly unexamined units;
- producer/method/version identity;
- timing/cost values without silent rounding;
- bounded native encoding under existing enclosing guards.

A failed capacity probe is evidence that the representation is not yet proven; it is not permission to proceed with a large port.

## F3 — Connected normal-product pipeline

Follow:

```text
shared native PR/dependency input
→ acquired source checkpoint
→ bounded caller/signature analysis
→ native comparison evidence
→ report/source projection
→ Workspace/store
→ fresh-process historical restoration
```

Normal product orchestration must be model-free where selected and must represent unperformed CI/runtime branches explicitly rather than fabricating empty evaluated evidence.

## F4 — Semantic equivalence and contamination

Mechanical relocation/refactoring may reuse the experimental transfer gate only if evidence equivalence is demonstrated across facts, paths, premises, outcomes, partiality/admission and limits.

A material semantic change requires successor qualification rather than claiming that source-code similarity or matching hashes alone proves equivalence.

## F5 — Controlled + fresh product proof

After the native bridge is connected, require:

- controlled/equivalence proof at each boundary;
- cold durable reconstruction without network/AST/checker/correspondence/synthesis replay where forbidden;
- separately frozen actual normal-product run;
- retained product report/source/Workspace behavior.

The old experiment runner itself is not product proof.

## F6 — Native adoption consequence

Decide whether the qualified native capability should cut over, remain dual/frozen temporarily, or stop for repair based on actual product-path evidence. Keep independent maintainer usefulness and runtime/compatibility conclusions separate unless later evidence establishes them.

**Done when:** Ali can supervise the native migration, detect evidence loss or ownership leakage, explain equivalence/non-equivalence, and state what the finished product path still does not prove.
