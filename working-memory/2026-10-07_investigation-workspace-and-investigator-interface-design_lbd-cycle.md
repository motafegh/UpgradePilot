### B1 representative traces

1. **Dependency/runtime path:** exact PR/source records → dependency transition/source contexts → workflow static consumption/runtime correlation → command-local package-manager semantics + exact execution → `RuntimeDependencyStateResult` → investigation snapshot → synthesis/report. The existing runtime composer is sufficient for its bounded proposition; the future workspace should retain/reference it rather than recompute it.
2. **Support-drop path:** authoritative release interval/source window → semantic candidate extraction → deterministic candidate grounding → exact target declaration/relevance → mechanism-specific propositions/applicability → investigation snapshot → synthesis/report. This already demonstrates the intended proposal-versus-validation separation on a narrow path.
3. **Presentation path:** native results → `PublicPullRequestInvestigation` → deterministic maintainer synthesis + report projection → optional saved report. Projection explicitly drops some raw/history/model/config context, so it cannot become the canonical investigation ledger.

### B1 genuine missing responsibilities

The source trace does **not** reveal a missing universal evidence type or a need to replace current domain owners. It reveals a cross-domain product gap:

- one evolving investigation identity/current-state composition owner across native records, proposals, evaluated propositions/candidates, missing premises and relevant history;
- explicit references/lineage from derived records and conclusions back to exact native inputs and method identity, without forcing all domain evidence into one base class;
- general proposal and capability-request representation, host-owned binding/eligibility/admission, and separate execution/observation/failure records;
- observation ingestion and knowledge-update rules, including stale-input/revision handling and candidate/proposition refinement lineage;
- bounded Investigator views that distinguish what exists from what was delivered/examined/cited/evaluated as support;
- recoverable retained investigation state distinct from the human/saved report projection;
- an interface by which synthesis consumes evaluated knowledge while retaining separate recommendation/action authority.

**Adapter rule carried into B2:** add an adapter only when a cross-domain consumer genuinely needs a stable reference/projection that a native owner does not already provide. An adapter must preserve the native record’s identity, scope, provenance and limitations; it must not reinterpret or duplicate the domain fact merely for workspace uniformity.

**B1 conclusion:** the existing product is not missing a generic “reasoning core.” Its strongest current property is the separation of domain-owned evidence/evaluation boundaries. B2 should therefore compare composition approaches by how well they preserve those owners while adding evolving cross-domain state. This finding favors composition/reference over duplication, but it does not yet choose among the B2 alternatives.

## A2 gate closure

Ali explicitly accepted the orientation and supplied his own reasoning at the pre-B gate:

- A passing CI result or any other isolated evidence/subset must not self-authorize a compatibility/final conclusion. The proper decision/evaluation owner must reason over the relevant evidence boundary, and a conclusion must preserve reasons and provenance rather than reduce to unsupported prose such as “CI passed, therefore compatible.”
- Evidence use must be traceable. The system should record which evidence supported a conclusion and, where one evidence/result was derived from other evidence, preserve that derivation relationship so later diagnosis, audit and debugging can reconstruct the path. Availability alone must not be confused with actual use.
- The distinction between the current fixed-sequence `PublicPullRequestInvestigation` result and a possible evolving workspace is understood. No premature combination, expansion or replacement is selected; B owns the actual alternative comparison.

This clears the canonical A2 pre-B understanding gate. It does not select a workspace architecture, evaluator, model, framework, persistence method or Investigator policy.
