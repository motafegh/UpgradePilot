## Living orientation map and initial reconstruction

Exact observed investigation inputs → captured source text plus declarations/requests/association/selection/coverage/policy/cost receipts → exact analysis input/run → native records with actual producer support and input edges → ordinary host/checkpoint → fixed cold projection. Reconstruction does not acquire evidence, parse Python, run the worker/checker, synthesize or grant maintainer authority.

Existing retained source catalogs often have capture_metadata=None. Actual ordinary acquisition summary preserves declarations/import candidates, request origins, module repository/revision/path/hash/size, association basis/provenance state, tag→commit summaries, dependency metadata, target coverage, omissions, transport events/recovery and source work. It does NOT retain every original release/project-link/publisher/tag observation. Historical receipt summaries must carry explicit gaps; do not synthesize missing native observations or mislabel a retained-experiment projection as fresh product acquisition. Native layouts must also admit complete future producer observations using existing PyPI/GitHub evidence types, without narrowing source responsibility to historical deficiencies.

Normal product acquisition and application/CLI/report integration remain subsequent. This cycle proves native family/material/store behavior with clearly labelled retained/control input; it does not claim a normal fresh product run, default profile cutover, runtime compatibility or usefulness. Keep frozen captures unchanged and use no provider/credential/model/target execution or enlarged limits.

Implementation choices: domain-owned explicit flat source-family root plus fixed receipt layouts; comparison root reuses the earned result wire without duplicate text. Source-dependent comparison decoding receives the exact decoded source family explicitly; avoid opaque JSON strings and a second source store. Existing unsupported/missing version gaps stay intact for old families; only the new supported method/version pairs receive admission. Partial source progress and failed analysis remain different records/outcomes.
