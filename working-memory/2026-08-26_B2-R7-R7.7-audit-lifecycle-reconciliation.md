## 1. Bounded responsibility

R7.7 reconciles the canonical audit lifecycle after the accepted R7.6 architecture/proof review. It does not add or change product semantics.

The lifecycle question is:

```text
for each canonical audit still classified as active
→ are its material findings still current engineering inputs?
→ or have stronger accepted owners/completed work incorporated them?
→ if a valid question remains open but unselected, defer it
→ keep scheduled work scheduled until its exact trigger is satisfied
```

Lifecycle meaning remains owned by `../audits/LIFECYCLE.md`:

```text
active    = selected input to current engineering work
scheduled = selected future responsibility with trigger + owning plan
deferred  = valid but unselected / no committed activation point
absorbed  = material conclusions incorporated into stronger owners
```

An absorbed audit can still be useful historical evidence. A future new trigger may justify a new review, but historical future-looking questions do not by themselves keep an audit active after its material conclusions are incorporated.

## 9. Learning closure

The important distinction from this slice is:

```text
historical audit mentions a future question
!= audit must remain active
```

Lifecycle follows **current engineering responsibility**, not whether an old document contains any sentence that could become interesting again.

Use:

```text
material conclusion incorporated into stronger owner
→ absorbed

valid unresolved question still exists, but no current selection/trigger
→ deferred

explicitly selected future checkpoint + trigger + plan
→ scheduled

selected input to the work happening now
→ active
```

That prevents two opposite errors:

- keeping old audits permanently active after their architectural purpose has been incorporated;
- marking a genuinely unresolved future responsibility absorbed merely because current implementation moved on.
