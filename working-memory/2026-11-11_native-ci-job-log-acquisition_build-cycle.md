## Results and checks

### Implemented component
- `src/upgradepilot/github/job_log_transport.py` implements a **single** exact GitHub job-log GET, manually validates the short-lived HTTPS redirect to an admitted Actions storage host, and transfers bytes in 8 KiB chunks under a hard **256 KiB decoded-byte ceiling** (caller may select a smaller cap). It accepts either the documented 302 or direct 200, refuses further redirects, rejects non-UTF-8/empty content through the provider, uses no retries or implicit auth changes, closes response bodies, and keeps signed URLs out of errors.
- `src/upgradepilot/github/actions.py::GitHubActionsClient.get_failed_workflow_job_log` requires a selected failed job whose run, head and PR event agree with the existing exact-head run/job owner. Returns typed `WorkflowJobLog` with repository/head/run/attempt/job identity, original API source URL (not redirect URL), UTF-8 bytes, SHA-256, and bounded text hidden from `repr`. The method requires callers to supply the job from `get_workflow_jobs(identity, run)` for attempt membership; the log endpoint itself does not independently prove attempt membership.
- `tests/test_github_job_logs.py` has **7 focused test methods**, including wrong identity and job status, safe redirect and bearer stripping, anonymous mode, over-limit body, 403/404/timeouts, invalid UTF-8, empty body, unapproved host and second redirect. The initial focused run passed 7/7.
- Public-safe [live trial receipt](evidence/2026-11-11-av-tracer-native-job-log/receipt.json) includes only evidence identity, byte count, log digest and confirmed text-presence flags, not raw log or credentials.
