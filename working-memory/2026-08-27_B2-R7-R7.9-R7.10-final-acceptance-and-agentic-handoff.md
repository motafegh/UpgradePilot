## 10. Learning / ownership closure

The main engineering distinction established by the final gate is:

```text
newer documentation/lifecycle HEAD
!= new executable candidate
```

A documentation-only `main` can validate the frozen executable candidate when we first prove exact executable/test/verifier identity. Conversely, a clean sync alone says nothing about runtime correctness; runtime tests and live evidence answer different propositions.

The next learning responsibility changes domains: from deterministic evidence reconciliation to evaluating whether a bounded model-driven **planner** can choose useful read-only investigation actions while deterministic code retains authority, action admission, evidence semantics, and proof-strength promotion.
