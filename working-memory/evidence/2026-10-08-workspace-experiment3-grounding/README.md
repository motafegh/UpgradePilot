## Exact-target qualification and a discovered overbinding

One investigation lineage belongs to **repository + PR number + exact base SHA + exact head SHA**. New commits do not mutate that historical target, change exact-SHA source meaning, or automatically invalidate its historical native facts. `target_changed` refuses operation/continuation as though an old Workspace belonged to another exact target. Deliberately following a moved head would create a new exact target/lineage with explicitly admitted evidence reuse/revalidation rules; those rules are not implemented here. Same-target material changes remain separate basis checks.

A [metadata-only probe](target-token-correction.json) exposed overbinding in the initial grounding harness: its opaque token serialized the full native PR record, including title/state/ref metadata. A title-only change kept the exact target identical but changed that token. The harness now uses only the four exact-target keys, retains descriptive native metadata as evidence, and tests title stability versus a changed head. This is an experiment correction consistent with main's boundary, not an authoritative contract change or an in-place lineage-rebinding feature. The inherited E3 fixture uses a supplied opaque target and does not implement production identity normalization.

Experimental mechanics around that real flow exercise request/admission/attempt/observation, immutable history, separate proposal provenance, omitted/addressable delivery and explicit historical recovery/continuation. The omitted-citation probe is deliberately imposed on real retained content; current orchestration does not naturally produce it. No delayed-result interleaving, counterevidence, target movement, live capability/method change, duplicate asynchronous delivery, crash or race occurred in this public flow. Their synthetic tests remain correctly labelled pressure/defense.
