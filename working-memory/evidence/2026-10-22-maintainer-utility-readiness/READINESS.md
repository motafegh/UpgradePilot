## Exact engineering handoff

The next bounded technical responsibility is **matched normal-report and source-packet preparation**, subordinate to the existing usefulness plan. Preserve the full product responsibility: maintainers must be able to recover exact identity, supported meaning, source, uncertainty and a justified next step. This preparation supplies equal source access for evaluating that responsibility; it does not solve missing impact discovery or grant action permission.

1. Trace normal acquisition through the existing application/client seams before choosing recording placement. GitHub and PyPI clients already accept sessions; the application accepts clients and retains native progress. Prefer a developer diagnostic observing the normal path over a new product evidence engine or public schema expansion. These seams are implementation possibilities, not proof a correct recorder already exists.
2. Define a pre-execution acquisition manifest with exact selected repositories/PRs and expected base/head, allowed anonymous endpoints, per-call/batch/bytes/elapsed limits, source/output identity, timeout/partial-failure handling and credential isolation. Cases are exposed development material, not unseen validation. Original source/reviewer conclusions must not enter acquisition input.
3. Retain the actual normal producer's source bodies/status and exact request identity where needed by the scoped ordinary-review task, with observation timestamps and explicit absent/failed sources. Retain a source-to-report coverage map. Keep private decoded response bodies outside Git with public-safe hashes/receipts. Do not log credentials, session headers or unrelated host data. Do not change provider/correlation/parser outcomes to complete a packet.
4. Generate the report and baseline-access packet from the same acquisition; baseline access contains admissible source evidence, not report findings, model-selected excerpts or expected answers. An API response error/empty query remains an attributed observation, not a general negative claim. A richer baseline acquisition is a different condition and requires explicit comparison disclosure.
5. Decide model requirements explicitly before any fresh call: Soup Sieve's successful historical finding used a model. Inspect current source/normal producer reachability; do not assume all three fresh runs remain no-inference. If inference is necessary, admit its exact method/budget/freeze separately or retain the unavailable case and select a justified alternative before outputs. A previously preserved interpretation is not fresh end-to-end automation.
6. Verify recorder transparency with controlled normal producers and failure/partial/malformed paths, then demonstrate exact matched packet/report composition on the declared normal capture. Keep incomplete/refused cases in the denominator. Capture preparation is mechanical proof, not independent usefulness or semantic acceptance.

No new recorder, fresh acquisition, model call, reviewer assignment or study freeze is claimed by this handoff. A utility-specific source packet need not become a permanent product capture API. Select durable retention/schema changes only if the normal named consumer genuinely requires them beyond this diagnostic trial.
