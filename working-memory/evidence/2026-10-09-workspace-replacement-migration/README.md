# Experiment 4: replacement migration feasibility

**Research result for review, 2026-10-09.** One normal offline product producer sequence can populate immutable experimental Workspace revisions and feed the current synthesis/report consumers through a one-way proof bridge without a second acquisition or domain evaluation sequence. Direct field projection is rejected by the existing synthesis type boundary. Cold checkpoint-to-native consumer materialization remains blocked by the unimplemented native codec. **No production cutover or compatibility requirement is established.**

## Scope and observed flow

[Native capture and bridge](../../../experiments/workspace_replacement_migration.py) use the **actual `investigate_public_pull_request` entry once per backend trial**, with controlled offline ports following current native/test patterns. Native functions run unchanged under delegating invocation capture. The fixed requirements patch establishes demo 1.0→2.0; exact synthetic workflow/runtime records supply one command-completion witness and one unresolved environment. The upstream native source-window/grounding route uses an explicitly supplied deterministic candidate extractor, then current target/impact owners refine `unresolved → established_applicable`. This is known fixture development evidence, not provider acquisition, model interpretation or unseen acceptance.

Capture records the producer's material arguments/results before local `source_contexts` and CI `coverage_inputs` disappear from the frozen return. It retains the actual requirements patch, three exact synthetic texts (workflow, changelog, target declaration), native inputs/results, extraction window/method/proposal and field bindings. The prototype uses E1 immutable successors and the E3 host-only checkpoint port backed by E2 provisional SQLite WAL/FULL. The consumer bridge contains no SQL/storage semantics.

## Failed approaches and corrections

- [Native-path setup correction](fixture-path-correction.json): omitted `ChangedFile.patch` made the current dependency owner return `missing_dependency_patch`, stopping the intended branch. Correct the fixture with an explicit patch and valid changelog-discovery record. Do not manufacture base/head acquisitions: this native path interprets validated patch evidence, unlike the earlier manually composed full-file corpus.
- Direct Workspace/native-field consumer calls were tried and rejected by the actual synthesis type check. Copying semantic rules, monkeypatching the type guard or subclassing the legacy result to conceal the dependency would not demonstrate replacement; retain a precisely limited one-way projection for parity instead.
- [Call-proof correction](call-proof-correction.json): eight early green tests did not make flat counters sufficient. A separate control called a native owner after capture ended and observed unchanged counters. Add independent application/domain re-entry refusal and a regression through both aliases, then rerun focused/broader proof. This control is excluded from the normal trial counts.
- Arbitrary tag-based native-object hydration, automatic native reruns on restore and a second legacy acquisition path are rejected. Preserve the codec gap rather than turn restored data into trusted owner results without an admitted method.

## Consumer cutover and legacy retirement

| Current owner/caller | Migration direction and retirement condition |
| --- | --- |
| `investigation.py`: fixed sequence and legacy constructor | Capture native inputs/results at their actual producer/composition boundary into Workspace; replace the final legacy constructor with explicit native/lifecycle publication. This experiment's delegating hooks are proof instrumentation, not proposed production interception machinery. |
| `maintainer_action.py`: input type check and `source_investigation` | Accept an explicit Workspace/native projection while preserving the admitted abstention/action prerequisites and material unknowns. Change retained source association deliberately; do not infer permission from lifecycle completion or report fullness. |
| `report_projection.py`: native-family helpers and synthesis call | Read one-way native Workspace inputs and source/basis identity, reuse the existing report contract/semantic assertions, and disclose newly available lifecycle/retention limits appropriately. Sequential report-local source IDs need not become canonical IDs. |
| `cli.py:main` | Wire acquisition into Workspace → synthesis/report. The saved-report `--open-report` branch stays its separately owned offline consumer. Introduce canonical Workspace open/continuation only under its own admitted recovery/authentication boundary. |
| `report.py` / `report_file.py` | Preserve report meanings, strict codec and save/open behavior. These types do not justify retaining an independent legacy producer and cannot restore canonical native/history state. |
| Active tests and scoped diagnostics | Move normal producer/synthesis/report/CLI assertions to native/Workspace inputs when production cutover is authorized. Preserve unique semantic evidence, then remove obsolete constructor/adapter-only tests. The R6 developer diagnostic and historical planner/LangGraph experiments also reference legacy results; review their real remaining proof obligations rather than preserve a product type solely for dated tooling. |

**Bridge reason:** current synthesis/report input requirements and an independent before/after parity oracle, derived only from the same Workspace's byte-bound live producer values. **Loss boundary:** no revision/basis history, full material-input bundle, view/use/proposal/evaluator lifecycle, gaps or unfinished obligations can round-trip through the legacy result. **Removal/reassessment trigger:** direct consumer inputs preserve native meanings and action limits under product tests, with no remaining admitted caller or external compatibility obligation. No such external obligation was found in inspected runtime consumers; this is not an audit of installed external callers.

Retirement also requires admitted native capture/codec and schema evolution across the supported families, truthful gap handling, native authority/reference validation, coherent lifecycle/recovery/continuation, and a supported rollback that preserves new canonical history. A legacy projection or saved report cannot become the recovery source or second writable truth store.

## Recommendation, debt and review boundary

Prefer **direct consumer cutover** in an explicitly authorized production design/build, preserving native/synthesis/report owners and their meaningful assertions. Keep this bridge as experiment parity machinery; its existence does not earn production retention. Maintain the provisional SQLite WAL/FULL baseline, file-store evidence and all earlier durability/policy limits. No performance result here earns a different storage technology.

Broader native-family/capture debt remains: uv/optional-extra/group transitions, conditional activation, other runtime managers/environment surfaces, actual artifact/wheel-target compatibility, malformed/unavailable provider inputs and full extraction/model provenance. The fixture's publisher/provenance/tag records are supplied typed controls; it proves invocation/composition, not external authentication. General semantic/adequacy evaluation and cold native hydration remain unsupported. Raw provider capture/privacy, selective retention, physical-write amplification, power-loss durability, replay and production activation require their separate owners/proof.

[Tests](../../../experiments/tests/test_workspace_replacement_migration.py) independently verify native state/owner inputs, complete consumer parity, explicit loss, missing/altered native material, wrong-target refusal, cold-codec refusal and the call oracle. [Verification](verification.json) records scoped regressions/source/static checks and non-proof. Main remains responsible for final method/technology decisions. **Stop at experiment-4 review; no production cutover, main merge or H1 mechanism change.**
