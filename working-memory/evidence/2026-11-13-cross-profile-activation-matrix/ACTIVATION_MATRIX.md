## Interpretation and the next proof needed

**What now has positive real-world coverage:** installed package/CLI and report delivery; exact PR acquisition and PyPI artifact/source facts; one case with deliberately preserved missing CI/upstream states; another with **actual model invocation, independently source-grounded interpretation and exact target Python non-overlap**; and historical opt-in source/CI log recovery.

**What remains materially unqualified on a current, still-actionable PR:** a normal-route end-to-end demonstration of **accessible exact-head run/job/step evidence correlated to supported changed-dependency consumption**, an actionable maintainer's use of the evidence, and any non-`abstain` action permission. In Q1 — CARLA/OpenCV, execution records were unavailable despite workflow configuration. In Q2 — Pydantic/Soup Sieve, run and job records existed, but step details were absent and matrix/`uv` relationships exceeded admitted proof. Neither should be called a product bug solely from that absence. Distinguish successful CI reporting from actually executing the changed version.

**Candidate next qualifying operation (not yet admitted):** use the plan's **conditional Q4** to transparently screen up to three **open/actionable Python dependency-update PRs** with still-available exact-head GitHub Actions jobs **and step records** plus source-level supported dependency consumers; explicitly preserve no-match screens. Freeze/admit **at most one** new full normal public-CLI run if it resolves the observed decision-critical CI/runtime ambiguity. This is justified by the real gap, not by a desire to increase arbitrary case count. If none meets evidence eligibility, record `more_evidence:<specific_missing_condition>`, rather than substituting a stale case or increasing model calls.

**Separate decision-review obligation:** after technical qualification, evaluate whether the reports guide maintainers to a defensible next action. Current deliberately abstain-only `maintainer_action` cannot be represented as positive merge/block/defer permission, and an eventual merged/closed PR is not validation ground truth. Compare report clarity, actual inspectable sources, uncertainty and maintainer reasoning, not just code coverage or exit codes.

**Research—not authorized Build:** Q1 strict publisher-provenance policy coverage for old releases; Q2 static matrix/`uv` correlation with valid runtime steps; target-declaration and publisher selected-facts original-source/reader gaps; inference-model provenance. Keep each hypothesis with a falsifying test and security boundary. The accepted project should not be changed merely to make a predefined case appear to pass.

**Operational safeguard after the two live cases:** An independent review found that the minimal subprocess supervisor could incorrectly complete timeout cleanup when a process leader exited but its descendant ignored `SIGTERM`. A group-wide escalation repair and [new regression proof](../2026-11-13-qualification-supervisor-timeout-repair/RESULTS.md) now pass alongside **1,126 full-suite tests**. The original two product invocations exited normally and remain unchanged; the next live case must use the repaired supervisor.
