## Useful, partial, refusal and stop criteria

Useful structural evidence requires at least one target-rooted path with both native old
and proposed version comparisons providing inspectable local binding/reception facts,
retained full selected source, path and explicit premises. Continued binding can be useful;
no mismatch or specific historical answer is required. Current sampled adapters may differ
from curated historical versions and remain samples, never target resolution.

Candidate-limit exhaustion preserves the first admitted comparisons plus
comparison_candidate_limit and any omitted diagnostic count. It is **partial coverage**;
the attempt must not claim all relevant paths examined. If useful paired facts remain,
record useful_partial_structural_evidence. If only unknown/one-sided/zero comparisons
remain, record insufficient_structural_evidence, even if analysis completed. Apply the
same honesty to path/depth/state/source/provider limits. Never enlarge a cap or select a
convenient subset to make the attempt pass.

Retain and stop on credential/auth failure, drift, missing complete native change evidence,
provider/size/time/source/worker bounds, invalid saved/code/material identity or an
unadmitted execution/host/budget need. No automatic retries, second case, model call or
frozen-case repair follows. A later attempt requires a separate recorded successor decision.

Valid comparisons do not establish actual installation, dispatch, semantic argument validity,
CI exercise, whole-update compatibility, maintainer action permission or native adoption.
Independently distinguish a legitimate unsupported case from an evidence-backed defect.
