## Implementation and same-input gain

Qualified files → existing scoped bindings plus new argument/signature facts → explicit curated pair/receiver premise → argument binding → saved JSON/source companion → offline summary/source views.

- [api_call_signature.py](../../../experiments/api_call_signature.py) extracts full-span facts and compares supported binding without evaluating retained source. Shared keyword/origin facts are reused through exact trace joins; no package-specific rule or second import analyzer is added.
- [api_call_signature_trial.py](../../../experiments/api_call_signature_trial.py) owns compare/open, file/target/reference integrity, immutable attempts and a bounded worker. A fixed sibling sources.json preserves selected full files through the existing catalog codec.

[Consumer controls](../../../experiments/tests/test_api_call_signature_trial.py) protect composition, unknowns, identity, resources and offline inspection.

The method covers ordinary positional/named arguments, required/default parameters, positional-only/keyword-only kinds, duplicate assignment and variadic reception. Caller expansions stay unresolved, while independently definite explicit keyword rejection survives. Receiver/constructor/descriptor/MRO/version premises remain explicit. Syntactic binding is never a safe-update verdict.

The existing baseline already exposes source text and ReferenceFact keyword/origin facts. It does not emit declared signatures or the complete conditional binding relation. The new result computes the app mismatch, preserves the old/new and outer/inner contrasts and keeps both sides inspectable offline. Target/FastAPI context is retained, but discovering the chain is not automated by a curated selector.

This is an observable structural verification gain. No reviewer time saving, independently measured error reduction, broader model improvement or maintainer task benefit has been established. Historical model errors/results were not rerun or regraded.
