## Evidence-backed learning and handoff

There are three concrete lessons worth reviewing now that outputs exist:

1. **One mapping, two consumers.** A partial report can reuse owned CI meaning without inventing a whole application result or synthesizing an action. Whole-report parity and source-graph comparison protect this composition boundary.
2. **Available, evaluated and established differ.** The original model received the same native records. A branch labelled evaluated can still contain only unresolved outcomes, while a static supported result remains a valid narrower positive. Valid citations/proposal publication never supply the missing runtime or semantic premise.
3. **Correct records do not guarantee correct presentation.** Native/JSON proof and green keyword assertions missed the wrapper's newline loss. Preserving the entire rendered body was the discriminating regression. Separate repair-only artifacts preserve the failed first result while proving the bounded correction.

Build and its repaired presentation proof are sufficiently evidenced for a learning/ownership walkthrough. Learner understanding is not inferred from AI-written code or green tests. Useful reasoning checks: trace how the whole and CI-only reports share meaning without sharing action authority; explain why the same delivered evidence did not make the original model recommendation adequate; explain what the render-only repair proves and why it does not justify an official rerun/regrade. E remains open for gap repair/defer and the next investment decision.

No follow-on model, semantic evaluator, richer native family, full FCI preparation or maintainer-action feature is selected automatically. Before choosing one, review the concrete outputs and the accepted report/usefulness route: this consumer establishes presentation faithfulness, while independent maintainer tasks/reviewers and broader interpretation quality remain separate proof obligations. Utility-study readiness can be assessed independently of further model development; this Build authorizes no reviewer contact or new utility experiment.
