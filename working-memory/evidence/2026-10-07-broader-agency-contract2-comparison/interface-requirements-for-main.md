# Experiment-derived interface considerations for main

Evidence: the complete [reviewed known-case comparison](README.md). Main owns the product Investigation Workspace and architecture. These observations define no product types, API, storage or implementation selection.

1. Preserve **available / delivered / referenced / semantically supported** separately, including available-but-unexamined evidence. Qwen receives the pytest root pointer, then describes retained release evidence as unavailable. A URL can identify a file already in the frozen corpus; navigation needs to preserve that relationship without treating external mention as external-only evidence.
2. Carry **source version, target binding, activation, capture authority and scope** into claim/recommendation review. Gemma assigns a9.0.0 warning to9.0.3 despite reading the correct interval. HTTPX illustrative reconstruction has proposed-head fields but is not independent runtime proof. Reference Starlette forwarding is not the installed target version. These are distinct propositions.
3. Make **negative observations and unknowns usable without turning them into absence/safety**. Literal httpx zeros do not exclude delivered FastAPI TestClient usage; proxy zero does not match proxies. An expired log endpoint does not establish global absence. Named critical unknowns must remain consequential when synthesizing advice.
4. Keep **stage completion and investigation adequacy** distinct. Four Fixed stages fail reference mechanics while final reports validate. Even valid stages can infer runtime exercise from static commands. Expose both procedural outcomes and remaining semantic responsibilities.
5. Include observations for **empty files, failed reads and typed notebook evidence**. Qwen correctly observes empty files but invents source line1; a read/trial-event observation is the appropriate evidence kind. Its optional note mixes typed evidence IDs with a legacy string citation interface. Both routes need clarity; no retroactive salvage was used here.
6. Separate **recommendation admission from report completeness**. All eight reports can cite real delivered evidence while recommending beyond it. Range satisfaction, patch labels, standard SSL forms and partial green captures must not silently supply whole applicability/compatibility propositions.
7. Preserve **auditable identity versus host annotations**. Packet identity currently hashes the original packet before attached reference annotations. The posthoc reconciliation must use that documented basis; future interfaces should make the basis explicit rather than let consumers assume every serialized annotated observation hashes directly to its identifier.

No automatic deterministic-tool, critic, LangGraph, multi-agent or unseen-evaluation experiment follows from these observations. They identify measurable responsibilities for the joint decision, not a selected solution. No material evidence contradicts the hybrid direction; success of its future components remains unproven.
