## Preflight and finite execution contract to freeze *before* B

1. **Freeze input and environment:** exact UpgradePilot commit/branch/status and CLI entry point; PR repository/number/base/head/dependency/file scope by current public metadata; model/service/configuration and Python runtime. If the PR has changed, label the historical case and the current revision separately; stop or explicitly reselect instead of quietly comparing changed identities. Separate prior runs from new run horizons.
2. **Model observability:** current `src/upgradepilot/upstream/support_drop_extractor.py` uses loopback `http://127.0.0.1:18080`, model ID `gemma-4-e4b-it-ud`, per-request timeout **180 seconds** and bounded upstream source window. The README previously said `127.0.0.1:12345`; it was corrected to `18080` on 2026-11-12. Verify the current code/service in the execution preflight rather than treating that closed documentation issue as an active blocker. Confirm model actually available under its adopted key; do not install/switch/download a model or silently change its configuration. Record whether model was **not reached**, **not activated due to prerequisite**, **POST attempted and transport failed**, **response invalid/unresolved**, **candidate rejected**, or **candidate grounded and target interpretation performed**. A report mentioning a model-related field alone does not prove that a POST happened. Do not publish raw prompts/responses by default.
3. **Capture routes must respect behavior:** use the **real ordinary public CLI** for both normal cases. Historical `tools/capture_report_sources.py` explicitly rejects non-GET/model POST and can be reused only for a deliberately **no-model** source-packet comparison, not unchanged for the Soup Sieve trial. If method/budget-friendly model POST observability is unavailable, use a small predeclared diagnostic wrapper or trusted local provider event/log receipt; do not build general instrumentation merely for the batch. Mark unobserved request/byte/token counts unknown, not zero.
4. **Resource/credential limits:** propose **one live attempt per admitted normal case**; default no target-code execution, workflow rerun, repository writes or patch mutation. Freeze for each case a physical HTTP request ceiling, per-body/aggregate decoded-byte ceilings, wall-clock deadline (allow for the 180-second model timeout when applicable), max local model attempts and no automatic retry. Use anonymous access unless 403/rate-limit requires deliberate `--github-auth token-env` with the existing owner-only token and process-scoped GitHub proxy bypass. No global proxy/network changes, credential printing or hidden fallback.
5. **Retain and inspect:** private unique directory per case outside Git, strict permissions, exact `--save-report` JSON, successful offline `--open-report`, actual source IDs for `--show-source` or `--show-facts`. For the combined profile, separately retained SQLite exact revision and excerpt recovery. Record report bytes and SHA-256, source kind/count and *actual retained text* versus reference-only links, source owner/citations, status/exit/stop reason and whether the loaded model was **observed**, rather than inferred. Public-safe receipts, stage-coverage matrix and selected annotated report passages may be committed after sensitivity review; don't automatically publish unreviewed raw API bodies, prompts, tokens or private Workspaces. Ali's decision to preserve the existing reviewed AV-Tracer archive is not blanket authorization to publish new sensitive captures.
6. **Independent correctness review, not a usefulness benchmark:** select at least one consequential claim per live report and verify its source/proof class, plus one missing/unavailable state; compare report claims against what the activated producer actually retained. Do not use the report's own paraphrase as source ground truth. Preserve false/conflicted claims and cases with no useful next check. An exit status of zero proves successful *report delivery*, not all branches, safe upgrade or useful maintainer decision.
7. **Performance envelope:** actual startup-inclusive wall time, call counts and HTTP response/decoded bytes **where observed**, model requests/latency/token usage when supplied by provider, saved file count/size/digests, offline reopen time and any setup cost separately. Network conditions and model configuration make times snapshots, not throughput benchmarks. Avoid declaring product reliability percentages from three handpicked cases.
8. **Decision and stop:** after two fresh normal cases plus previously verified AV-Tracer reference, identify (a) actually reached capability families, (b) broken/non-activated or unsupported stages, (c) missing source retention/inspectability, (d) the most consequential maintainer decision the product can or cannot support, and (e) the earliest owning producer/consumer behind any failure. Recommend one bounded Build, no Build, or a precise follow-up evidence need. Keep human usefulness and general correctness unproven. Do not start an AI-only reviewer study.
9. **Random sampling only as a separately selected step:** after the deterministic batch, freeze an eligible universe/selection frame (e.g. supported recent Python dependency PRs with documented exclusions), seed/method, observation horizon and denominators. Include every selected attempted outcome, rate-limit and unsupported result. A random sample estimates outcomes **only in that declared sampled frame**, not all Python PRs or global usefulness. Do not start it simply because deterministic cases succeeded.
