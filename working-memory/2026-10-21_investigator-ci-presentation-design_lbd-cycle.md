## Source trace and early design correction

Product path: investigation.py completes/publishes native progress and returns PublicPullRequestInvestigation carrying workspace_revision and producer results; cli.py calls project_investigation_report, then render_investigation_report/save_report. report_projection._project_ci copies run/job source facts, coverage/workflow assessments, runtime command assessments, scoped unknowns and sources into existing Report* records. It does not re-evaluate CI. The human renderer preserves assessment state/detail/proposition/strength plus unknowns and independently synthesized action. This existing projection already keeps supported positives and unresolved command outcomes separate.

Experimental path: InvestigatorAssignment ingests a captured boundary into its fresh host; WorkspaceEvidenceAccess validates/reconstructs the offered four CI/native families for native reads. SuppliedEvidenceTrial/trial packing delivers native records and source material. The model writes REPORT_SCHEMA summary/claims/conditions/recommendation/stopping_reason. publish_report checks the shape, readiness, material validity and visible typed references, then stores an attributed laboratory_report proposal and asks the host's proposal evaluator. It explicitly does not establish entailment. There is no call to product report_projection and no deterministic final CI composition here. Existing typed evidence delivery therefore does not protect the model's final text from unsupported CI promotion.

Important reuse constraint: project_investigation_report requires the full application result and runs maintainer synthesis; CINativeProjection exposes only the four admitted native families. Fabricating a full application object to call the full projector would invent unretained/non-evaluated context. _project_ci is a private whole-report helper tied to its accumulator; direct private callability is not an admitted standalone CI interface. A useful reuse design must expose the smallest honest CI-only projection, sharing the existing mapping rather than duplicating CI truth or manufacturing full-result/action state.

Early correction: a native CI appendix alongside unchanged model summary/recommendation does not make the combined output faithful. A deterministic owned CI view must remain distinct from the original attributed proposal, with no model-authored global summary/recommendation presented as the accepted CI conclusion. This narrows the first capability to faithful CI presentation, explicitly leaving model semantic adequacy unresolved. Any later combined semantic report requires its own admitted assessment/acceptance; no keyword contradiction filter, critic or extra prompt follows automatically.
