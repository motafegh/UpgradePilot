## Living orientation map and frozen contract

Flow: declared release/index/tag/path acquisition → exact acquired text → section examination → complete-window admission or typed incomplete evidence → shared experiment manifest projection → source-only and ordinary-PR writers. Adapter replay consumes target facts and does not interpret upstream windows.

- Successful windows keep their existing result type, exact section contents/order and hashes.
- Selection failure remains `AcquisitionProblem`; its evidence retains the acquired repository/revision/path/hash, required versions, all matching section candidates/ranges/hashes, per-version absence/ambiguity and order/overlap/size issues. Acquisition retains the already established declaration/provenance/index/tag context alongside that examination.
- No-match means absent **or unsupported by the exact-heading grammar**; it does not prove that the release has no documentation. Duplicate matches never select a winner.
- Candidate text is retained whole only when aggregate candidate text fits the caller's character budget. Otherwise all candidate text is omitted with an explicit reason, while exact ranges/hashes remain. No smaller window is admitted and no oversized source text is exported.
- Incomplete evidence has no complete-window hash/coverage or eligibility for complete-window interpretation. A recovered section supports only its scoped examination; API meaning remains unimplemented.
- Both actual manifest writers preserve this contract through one focused serializer. Product authority types and report v1 stay outside this increment. No model call, target installation, general CFG analysis or alias refinement is selected.

Retention justification: selector is the earliest sufficient producer; typed candidates/examination distinguish retained observations from admitted complete windows; an acquisition wrapper retains upstream provenance without broad object serialization. A shared small manifest module avoids divergent retention behavior in the two existing consumers. No dependency/framework is added.
