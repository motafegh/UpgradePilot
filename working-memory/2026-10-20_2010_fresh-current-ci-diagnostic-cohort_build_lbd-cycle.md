## Working design

New series: `FCI` = Fresh Current CI diagnostic. It is intentionally distinct from historical S001–S016 and is exposed development/diagnostic evidence only.

Proposed root: `product-simulation/fresh-current-ci-diagnostic-2026-10-20/`.

Per admitted case:

```text
cases/FCIxxx-<slug>/
├── manifest.json
├── raw/
│   ├── github-api/
│   └── source/
├── derived/          # only when deterministic/native outputs are later produced
└── review/
```

Raw policy: exact captured provider responses and losslessly retained source bytes are immutable after publication. Later corrections or interpretations are additive overlays outside `raw/`; hashes in the manifest bind every retained object. Git history provides an additional immutable publication identity.

Required identity: repository, PR number, base SHA, head SHA, dependency, old version, proposed version, observation/acquisition timestamp.

Required provider material where available/needed: exact PR metadata, exact PR changed-file response or diff/patch establishing the transition, target-revision workflow source bytes plus provider retrieval identity, exact-head pull-request workflow-run response, exact run-attempt-specific job responses, runtime step summaries, and any additional current-producer input actually required. AI/manual propositions are never promoted to producer input.

Job-step state is explicit per captured job response: `field_absent_or_unavailable`, `empty_array`, or `non_empty_array`. A successful job does not establish dependency installation/exercise.

Logs/artifacts are opt-in only when materially required after size/security/privacy review. Current correlation uses run/job step summaries rather than logs, so default is not to retain logs unless a selected case exposes a concrete need.

Qualification labels: `qualified_for_current_ci_diagnostic`, `qualified_as_unresolved_control`, `rejected`.

## Admission target and stop line

Aim for 3–5 cases, not maximum count:

1. at least one ordinary workflow with current non-empty runtime steps and a realistic supported-correlation path;
2. at least one structurally different Python case, preferably tox/environment-oriented;
3. at least one legitimate unresolved/control shape current contracts should refuse rather than guess, preferably matrix/reusable/dynamic identity or genuinely unavailable runtime relationship;
4. extra cases only for a distinct diagnostic responsibility.

Stop discovery once the cohort covers those responsibilities with exact frozen evidence. Do not select cases because their expected result is desirable.
