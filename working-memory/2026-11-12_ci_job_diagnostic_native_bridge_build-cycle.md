Design notes:
- Exact run/attempt/job is **user-selected** and must be revalidated against GitHub's selected run metadata and *attempt-qualified* job listing, not merely the job URL. No auto-targeting unrelated E2E jobs.
- Native CI observation is an optional family, not an extra placeholder on existing source-only captures. Retain bounded safe error substring/line index, digest, URI, package install token only when explicitly present; no raw full job logs in report/public Git. Provider full body exists only in process memory and is discarded after interpretation.
- A single selected job requires at most four physical HTTP requests (run, one job page, log redirect, storage body), in addition to the existing source acquisition policy; report provenance records the separate budget. No retries/fallback tokens.
- A matching error keyword in log and source witness is supportive **textual agreement**, never an assertion that the source analysis corresponds to the loaded version/callable or that this change uniquely caused the entire workflow failure.

## Actual Build result and verification receipts

**Native delivery / public interface.** `--evidence-profile caller-signature-ci` explicitly requires frozen `--expected-base` / `--expected-head`, one selected `--ci-run-id`, `--ci-run-attempt`, `--ci-job-id`, and a private `--workspace-store`. Existing `caller-signature` profile and default normal investigation semantics were not changed. Selected GitHub Actions run-attempt metadata is checked against the frozen PR number, base/head and event before selecting exactly one failed job in the attempt-qualified jobs listing. The existing exact-job provider then enforces bounded log retrieval and protected redirect authentication. A positive summary cannot be silently joined to a different run or attempt. Run/attempt/job selection is explicit; this is **not** automatic CI problem discovery.

**Evidence representation and scope.** `ci/job_log_diagnostic.py` retains only a recognized, bounded Python unexpected-keyword `TypeError` text, the first matching line and optionally an exact observed `Successfully installed package-version` token with position; the original full job log is not checkpointed. Repeated identical pytest traceback/summary error text is deduplicated, while different errors or no matching form yield `unclassified_log`. HTTP access refusal yields `unavailable`, not a fabricated absence of failure. The optional `ci_job_log_diagnostic` native family uses an explicit v1 typed layout and published producer identity; it is **outside** the default `FAMILY_CONTRACTS` inventory and is not inserted into ordinary/historical source-only captures. Offline reconstruction verifies the exact PR/head/source URL, 64 KiB cap, valid source digest and internally consistent text, token, state and position. Report projection adds a selected-source excerpt with digest and links, retains `abstain`, does not assert the loaded HTTPX module identity, upgrade-caused regression or whole-run causality; full CI dependency coverage and runtime-state stay `not_evaluated` in this profile. The combined report has an installed method identity distinct from the original source-only report, with fresh-process cold reopening proven.

**Meaningful failures and repairs.** The first new controlled path run failed solely because the new test used a nonexistent `CheckpointStore` context-manager interface; this test harness was fixed. More importantly, the **first full regression suite failed** (1,112 tests; 12 failures and 27 errors) because the initial optional CI family was mistakenly added to the default `FAMILY_CONTRACTS` mapping; that changed historical normal-capture structure and broke reconstruction controls. Repair: register the new CI family only in `_OPTIONAL_FAMILY_CONTRACTS`, dispatch it explicitly by `family_contract`, and preserve the original default family order and placeholders. The subsequent targeted native reconstruction suite passed 42/42 and the complete suite passed 1,113/1,113. Further improvements tightened selected run association to exact PR number/base/head and accepted duplicated identical traceback lines without disguising different errors; native reconstruction now refuses internally forged rejected-keyword facts even when their payload digest is recomputed.
