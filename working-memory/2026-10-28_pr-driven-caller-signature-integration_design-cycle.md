## Current-source reconciliation

1. `acquire_dependency_inputs` already returns the initial PR observation/description, validated changed files, native dependency result and source contexts. The normal product uses it; the older experimental ordinary-PR function still directly obtains PR identity and dependency analysis. Reuse one prefix, not two acquisitions/evaluations with different observation horizons.
2. `acquire_public_pr_context` already starts from repository/PR and composes TargetContextAcquirer, declared release-window acquisition and adapter exploration. It is an experimental route, not the normal product CLI, and currently does not call the new checker.
3. TargetContext retains acquired files, imports, scoped references, declarations and omissions. Existing manifests retain source identities/hashes and facts without complete source bodies. They cannot supply a future offline source reader by hash alone.
4. AdapterSourceExplorer has exact-release/tag/tree inspection and per-run reuse, but samples the latest stable satisfying a declaration, only starts positive exploration from established imported references, and does not traverse relative-module forwarding. Its samples are not target resolution. Those are current supported boundaries, not defects.
5. DeclaredReleaseWindowAcquirer obtains source-attributed release material, not arbitrary old/proposed Python callable definitions. New signature-source requests must reuse source association/tag/inventory owners while preserving stronger resolver and publisher-conflict semantics.
6. Checker compare/open is admitted for curated selections; its reader explicitly marks that proof class. An automatically generated candidate cannot be silently relabelled as a curated result or vice versa. Reuse the core facts/checker and common decode/display responsibilities with explicit envelope compatibility.
7. Native capture has no API caller/signature family. Main report/synthesis still consumes mostly legacy result fields, while PR description and specific native consumers already reconstruct directly. A source catalog is data, not a parallel canonical investigation state. ADR0012/0013 control eventual product adoption and explicit cold reconstruction.

These facts refine the required connections without altering the agreed product goal. The trial must not earn acceptance merely by accepting an empty/all-unknown output when relevant sources/correspondence are missing.
