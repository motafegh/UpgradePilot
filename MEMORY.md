## F6 full investigation result and decision handoff

F6 asks whether the exact proposed dependency version is actually **present in the exact relevant CI environment after dependency consumption**. Current admitted dependency changes are exact-version based, so this is not range resolution.

The investigation established four important facts:

1. **F6 is a genuine distinct proposition.** Current `supported_runtime_correlated` correctly proves bounded execution of an admitted consumption occurrence, not resulting package state. Pip `--dry-run`, uv `--dry-run` / `--no-sync` / `--no-install-package`, and later uninstall/mutation are concrete defeaters against silently upgrading command success into post-state.
2. **F6 is normally feasible in at least one current product-shaped real case.** Public Dependabot PR `Jam3s97/Aruba_Device_Tracker#83` changes `ruff==0.16.5 → 0.16.8` in `requirements.txt`; exact-head CI succeeds; the target-owned Lint job log reports `ruff-0.16.8` installed and then successfully invokes ruff in later steps.
3. **Log evidence is not durable.** Existing real project anchor `googlefonts/glyphsLib#1145` still exposes exact run/job/step metadata but its historical job-log downloads now return HTTP 410, matching GitHub's bounded workflow-log retention model. Unavailable/expired logs must remain missing evidence, never negative evidence.
4. **Several source classes exist with different proof quality.** Human installer logs are reachable but text/retention-sensitive. Explicit package-state outputs such as `pip inspect` JSON, `pip list --format=json`, `importlib.metadata.version(...)`, `pip freeze`, and uv environment-inspection outputs provide stronger state semantics when targets already emit them. Public `idaholab/MontePy` demonstrates real Dependabot-pip configuration plus CI `pip freeze`, though the inspected recent range-update PR is outside today's exact-pin admission path.

The investigation also preserves a nearby owner question: some current pip/uv command-option shapes may deserve tighter classification at their existing parser/selector owners. F6 must not become a downstream patch for command semantics that should be controlled earlier.

**Decision alternatives preserved, none selected:** tighten current command semantics only; add a bounded installer-log witness; admit explicit package-state witnesses only; define a source-neutral F6 contract with staged adapters; or leave F6 unimplemented and use a targeted maintainer check only when the exact fact is decision-critical.
